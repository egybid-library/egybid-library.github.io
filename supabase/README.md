# إعداد المزامنة

1. افتح مشروع Supabase ثم SQL Editor → New query.
2. الصق محتوى setup.sql كاملًا واضغط Run. يمكن إعادة تشغيله دون حذف بيانات.
3. جرّب زر «مزامنة» في المعاينة المحلية. بيانات المشروع العامة موجودة في docs/sync-config.js.

لا يحتاج القارئ بريدًا أو تسجيل دخول. أول جهاز يفعّل المزامنة، والثاني يفتح رابط الربط ويؤكده، أو يلصقه في نافذة المزامنة. تتحد القوائم الموجودة عند أول ربط. الرابط مفتاح وصول عشوائي ٢٥٦ بت؛ حامله يصل إلى السجل ويعدّله، ويُستخدم للاستعادة بعد مسح المتصفح. QR يُنتج محليًا دون خدمة خارجية. يُحذف مفتاح الرابط من شريط العنوان، ويُرسل داخل POST عبر HTTPS فقط.

المفتاح العام في الموقع لا يتيح تعداد السجلات. الجداول داخل schema خاص، مع RLS ودون منح anon/authenticated صلاحيات مباشرة. الدالتان العامتان تتحققان من SHA-256 لمفتاح القارئ وتستخدمان search_path فارغًا. لا تُوضع مفاتيح secret/service_role أو كلمة مرور قاعدة البيانات في الموقع.

التخزين السحابي: معرف المقال، نوع العلامة، حالتها، وقت التعليم، مراجعة الخادم، ومعرفات منع تكرار الطلب. لا تُرفع المقالات نفسها. التعديلات تحفظ محليًا أولًا، ثم تُرسل على دفعات لا تتجاوز ٢٥٦. الإلغاء يُحفظ كحالة false وينتقل للأجهزة الأخرى. القارئ غير المربوط لا يرسل أي طلب إلى Supabase.

عند تعارض تعديل العلامة نفسها، يُعتمد آخر تعديل قبله الخادم، دون الاعتماد على ساعة الجهاز. تعديلات جهاز غير متصل تُرسل عند عودته وقد تكون هي آخر تعديل مقبول. معرفات العمليات تمنع طلبًا أُعيد بعد فقد الرد من إحياء علامة ألغيت لاحقًا. عمليات الجهاز المعلقة تغطي ردود الشبكة الجارية حتى يتم قبولها. تُرسل الفروق منذ آخر مراجعة، مع Web Locks لتسلسل الطلبات بين التبويبات، ولقطة كاملة في المتصفحات التي لا تدعم القفل.

تتم المزامنة بعد التعديل بمهلة قصيرة، وعند العودة للصفحة أو الاتصال، وكل دقيقة أثناء ظهور الصفحة. فصل جهاز يُبقي قوائمه ويوقف مزامنته فقط. إزالة نسخة الأوفلاين لا تفصل المزامنة؛ مسح بيانات المتصفح يزيل الربط ويحتاج استعادته من الرابط الخاص.

حدود أولية قابلة للتعديل في SQL: ٢٠٠٠ سجل، ١٠٠٠٠ علامة و١٠٠٠٠٠ عملية لكل سجل. راقب حصص الخطة المجانية قبل التوسع؛ هذه الحدود لا تضمن منع إساءة استخدام التسجيل العام. يمكن أن يتوقف المشروع المجاني عند قلة النشاط.

الاختبار: npm ci ثم npm run test:sync. الاختبارات تشغّل SQL الحقيقي داخل PostgreSQL عبر PGlite، دون لمس قاعدة القراء. بعد تعديل الموقع شغّل npm run build:search ثم npm test وnpm run test:offline وpython3 scripts/verify.py. البرامج وQR تدخل حزمة الأوفلاين، ولا يتغير محتوى المقالات أو تواريخ نشرها.

روابط localhost مخصصة للاختبار المحلي؛ ربط هاتف بالموقع العام يتطلب نشر النسخة بعد مراجعة المستخدم وموافقته. لا يتم النشر تلقائيًا بسبب إعداد Supabase.
